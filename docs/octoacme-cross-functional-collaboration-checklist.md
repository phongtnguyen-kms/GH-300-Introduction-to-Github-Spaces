# OctoAcme — Cross-Functional Collaboration Checklist

Use this checklist during planning, execution, release, and retrospective phases to improve role clarity, handoffs, and accountability.

## 1) Planning
- [ ] **Product Manager** confirms problem statement, outcomes, and acceptance criteria.
- [ ] **Project Manager** confirms milestones, dependencies, and communication cadence.
- [ ] **Technical Lead** reviews technical approach and major delivery risks.
- [ ] **Designer / UX Partner** confirms key user flows and accessibility expectations.
- [ ] **QA / Test Engineer** defines quality strategy for critical flows.
- [ ] **Security / Compliance Partner** identifies required reviews and controls.
- [ ] **Stakeholder / Sponsor** confirms priorities, constraints, and decision checkpoints.

## 2) Execution
- [ ] **Developers** deliver scoped increments with tests and documentation updates.
- [ ] **Technical Lead** monitors architecture consistency and dependency risk.
- [ ] **QA / Test Engineer** validates acceptance criteria and regression impact.
- [ ] **Designer / UX Partner** validates implementation fidelity on key interactions.
- [ ] **Project Manager** tracks progress, blockers, and escalations.
- [ ] **Product Manager** resolves scope trade-offs and priority changes.

## 3) Release Readiness
- [ ] **Project Manager** runs release readiness review with all key roles.
- [ ] **QA / Test Engineer** confirms test results and open-defect risk status.
- [ ] **Security / Compliance Partner** confirms required checks and approvals are complete.
- [ ] **Support / Operations Representative** confirms runbooks, alerts, and support readiness.
- [ ] **Stakeholder / Sponsor** receives go/no-go summary for milestone approval.

## 4) Post-Release and Retrospective
- [ ] **Support / Operations Representative** shares incidents, trends, and customer-impact data.
- [ ] **Product Manager** reviews outcome metrics against goals.
- [ ] **Project Manager** captures retrospective actions with owners and due dates.
- [ ] **Technical Lead** and **Developers** prioritize reliability and debt follow-ups.
- [ ] **QA / Test Engineer** records quality learnings for future planning.
- [ ] **Security / Compliance Partner** documents residual risks and remediation tracking.

## Why this checklist helps
- Clarifies who must be involved before handoffs occur.
- Reduces late-stage surprises in quality, security, and operations.
- Improves onboarding by making collaboration expectations explicit.
